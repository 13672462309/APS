# 生成排产候选方案

读取输入 snapshot、base_plan、feedback。各字段的数量单位为吨、时间单位为分钟。

1. `supply` 已包含在制。`wip` 是必须完成的固定余量；它由后端自动叠加，返回 quantity 只代表新增量，不能再次加入在制。
2. `minimum` 是逐日实际需求按分类覆盖期求和减供应得到的硬缺口。`minimum` 和 `target` 都是已经扣减供应后的“新增生产量”，不能再次减 supply；不是期末供给总量。quantity 必须从该物料的 `options` 中选择。0 只有在选项包含0时可选。
3. 优先补交付缺口，再考虑安全库存 `target`；不要为了OEE无限增加库存。补货不足可作为换型/均衡权衡，但必须在 reason 中解释。
4. 同半成品、同粒径尽量成组；参考每条产线的 `rate` 与 `batch`。同一SKU只能由求解器分配到一条线。
5. 读取 feedback 的未排任务、违规、负荷与指标。先消除硬约束问题，再改进软指标；不能少报必须完成的任务以提高分数。
6. 每次选择少量有针对性的变化。保持未变物料不输出。第一轮也可以无数量调整，采用合法基准方案。
7. priority 只允许整数1/2/3，1最高。focus 允许 balanced、setup、particle、valley、delivery，分别侧重均衡、换型、粒径、谷电、交付。它只是给求解器的权重提示，不是保证结果。
8. 不修改数据、阈值、评分权重、覆盖期或停止规则。不返回产线、开始结束时间、指标或伪造的求解结果。

只返回一个 JSON 对象，不加 Markdown，不输出工具调用或文件：

```json
{"adjustments":[{"product_id":"实际物料编号","quantity":22.0,"priority":2}],"focus":"balanced","reason":"简述选择及取舍，不超过300字","expected_effect":"需要实际求解验证的改进方向"}
```

所有 adjustments 均相对本轮 base_plan 生效。无调整时返回空数组。后端会拒绝未知物料、非法批量和改变硬需求的方案。
