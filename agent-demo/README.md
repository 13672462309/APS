# 饲料 APS Agent 本地 Demo

保留提供的前端界面基础，接入真实 Excel、AgentCore API 和原有 `aps-feed` CP-SAT 求解器。

## 启动

在 APS 文件夹的 PowerShell 执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\agent-demo\start.ps1
```

打开 **http://127.0.0.1:8765**。当前电脑已准备独立 `.venv`；终端 Ctrl+C 停止服务。换电脑使用 Python 3.11：

```powershell
python -m venv agent-demo/.venv
agent-demo/.venv/Scripts/python.exe -m pip install -r agent-demo/requirements.txt
```

保留 `.env` 中的 `AGENTCORE_ENDPOINT` 与 `AGENTCORE_ENDPOINT_API_KEY`。密钥只由后端读取，不进入前端或结果。单独测连通性仍可运行 `run.ps1`。

## Git 与本地凭据

项目根目录统一管理 Demo 和 `aps-feed/aps-feed` 求解器源码。求解器原有 Git 元数据保存在被忽略的 `.work/git-backups/` 中，不作为嵌套仓库提交。Office 的 `~$` 锁文件、虚拟环境、运行记录和 `.env` 均已忽略；`.gitattributes` 固定源码换行，Windows `.cmd`/`.bat` 保留 CRLF。

原求解器的数据库密码与 HPAAS client secret 从环境变量读取，未设置时读取旁边被忽略的 `aps-feed/aps-feed/credentials.local.json`。变量名为 `APS_MYSQL_ONLINE_PASSWORD`、`APS_MYSQL_OFFLINE_PASSWORD`、`APS_HPAAS_UAT_CLIENT_SECRET`、`APS_HPAAS_PROD_CLIENT_SECRET`，本地 JSON 使用相同键名。当前电脑原有值已保留，不能将该文件提交。Excel Demo 不调用数据库或 HPAAS，不需要这些凭据；在新电脑运行原生产接口时才需要另外配置。

Demo 所需的历史电价样例 `aps-feed/aps-feed/data/v2/1130-3.txt` 单独纳入版本管理，其余历史输入仍忽略。

## 使用

1. **对话排产**：保留原 HTML 的欢迎卡、快捷提问、六阶段进度和左右对话/工作台。点击“开始排产”，依次校验数据、分析供需、确认目标，再启动真实求解。
2. **查询与目标**：可输入“查询5000611的需求”“常规1覆盖2天”“OEE目标改为88%”“最多3轮”“优先减少换型”。右侧也可填写配置；点击“确认目标，开始求解”会先保存表单。
3. **最终方案后改量**：点击“修改产量”，或说“把5000611的总产量改成33吨”。先保存修改草稿，再点“确认修改，开始优化”。在制量固定，用户修改的新增量在整轮循环中锁定；未改物料可继续优化。非法数量会返回邻近合法选项，不自动取整。
4. **修改约束**：支持全天停用/恢复产线、物料指定产线/固定开始/最早开始/最晚完成、优化侧重点与循环停止参数。例：“5000611安排在二号线，04:00开始”。拖动甘特块也会生成同样的约束草稿，需要重新求解。
5. **解释与版本**：点击甘特块或问“为什么5000611安排在二号线”，查看需求、产能、换型及人工约束依据；支持负荷、计划明细、指标公式、建议采纳、前后甘特图及指标对比、CSV/JSON导出。旧版本保留，可切回再开分支。
6. **会话恢复**：刷新恢复当前会话；“会话历史”可以恢复完整消息、草稿和版本关系，也可载入独立求解记录。只有本地真实计算记录，没有伪造历史生产记录。

每条对话对应一个可核验操作。常见表达走确定性路由，其他表达交给已配置 AgentCore 解析为白名单 JSON；业务数据、参数修改、排程和指标均由后端执行。未知或有歧义的指令不修改参数。可先查询物料，再用“它”连续调整。当前复杂复合指令需分步输入；没有开放任意代码执行。

从最终方案修改后的循环：`旧版最佳计划 → 人工修改并校验 → 第一轮求解确认后的计划 → 后续 Agent 提案/求解/评估 → 保留本次最佳 → 新版本`。最多轮数包含第一轮，设为1时不会再调用排产 Agent；要迭代改进请设为2或以上。新版本不能直接拿旧版分数当候选，因为产量或约束已变。若新版本不可行，保留原版与未成功的修改草稿。

默认最多4轮、总预算600秒、连续2轮无显著改进停止；显著改进为综合分增加至少0.2分或硬约束表现改善。重复方案停止。单次Agent调用上限240秒、求解65秒，均受总预算约束；取消时最多另用3秒请求云端停止。未确认会明确提示，不自动重试。

## 需求列表与步骤导航

需求概况、物料明细、需求管理和库存监控共用图2的81字段目录。点击“列表设置”可搜索字段、显示/隐藏、冻结、调整列宽（60～600像素）和拖动排序；也可用上下按钮或 Alt＋方向键排序。点击“确定”后应用并保存在当前浏览器，刷新后保留；取消不保存。参考配置提供图2默认、仅已有数据和常用字段，“恢复”还原图2默认。操作列始终保留。窄窗口装不下冻结列时暂时取消固定，仍保留列顺序，可横向滚动。

字段区分Excel原值、计算值、口径映射和缺数据，悬停列名可查看来源。订单需求相关字段暂用Excel的物料级逐日需求映射；没有客户订单交期、实际月销量等数据的字段显示“—”，不填造0。原Excel不会被修改。`demand_fields.py`集中定义字段和计算映射。

需求确认只编辑“成品分解数量(吨)”，“计划产量(吨)”为该物料各分解行的数量之和。当前每物料一条分解行，两者相等，包含固定在制余量；可在需求表直接填写，也可打开分解数量编辑表。未填写时两列显示空值，不使用内部规则基准预填。保存后检查需求、整批、库存及在制约束，人工数量在循环中锁定；未填写物料由确认求解后的基准和Agent优化生成。保存本身不运行求解。内部求解器仍使用“新增量＋固定在制”的数量结构。“建议生产量”仅展示已求解可行方案的数量，求解前为空。

方案输出的“订单明细”使用原HTML的七列：订单号、物料、分类、产线、数量、交付、状态。当前按物料汇总真实方案（包括未排入的任务），不再在此页混排指标卡、甘特图操作及任务起止时间。客户订单号、逐订单交期尚缺，均显示“—”；不会用前置生产订单号冒充客户订单号。`order_details.py`按冻结快照生成明细，`static/production-views.js`保留原型表格样式。现有求解器仍不跨线拆分；展示适配器可以汇总同物料多条排程行，但不等于已开放拆线求解。

“查明细”后可点击“返回完整表单”恢复全部物料。当前所在步骤与已到达进度分别保存；可以点阶段条或上一步回退，再从当前步骤逐步继续。目标确认后需明确点击“确认目标，开始求解”，仅查看、返回或输入“继续”不会自动启动排程。

## 计算流程

`冻结Excel快照 → 合法数量边界 → Agent提案 → 参数校验 → 原求解器排程 → 独立核验及六项指标 → 反馈优化`

- 新增量下界 = max(0, 覆盖期逐日实际需求之和 − 表中供应)。供应已含在制，不重复扣减。
- 基准先补安全库存，再按产线混合机整批取量；Agent修改新增量和优先级、选择排程侧重点。为限制响应时长，每轮提供最多8个可调整物料，逐轮轮换；完整需求始终冻结。这是局部搜索原型，不保证全局最优。
- 同SKU在制余量与新增量合并成不拆线任务；新增量需整批，在制锁定且免整批。求解器决定产线、顺序和时刻。
- 保留原 Stage1分配 + Stage2排序算法，通过适配器注入Excel产能，不访问数据库，不回写生产系统。独立环境固定OR-Tools 9.10，避免此电脑上较新版本的原生崩溃。
- 始终保留最佳可行结果；软指标高分不能抵消硬约束问题。没有可行结果时只展示问题候选，不能视为可执行方案。
- 综合评分权重固定：粒径20%、交付30%、OEE20%、均衡20%、谷电10%。不适用项不参与，其余权重归一化。达标、轮数/时间/停滞上限、重复、手动停止，任一触发即结束。

## 六项指标

| 指标 | 口径 |
|---|---|
| 可行性 | 通过产能、整批、换型、不重叠和开班校验的计划数 / 本轮总计划 |
| 粒径 | 非递减相邻对 / 可比较相邻对；空粒径不参与 |
| 及时交付 | 生产日20:00前完成且通过校验的计划 / 本轮总计划；额外固定缺口及在制完成门槛防止漏报 |
| 理论OEE | 有效生产分钟 / 各已启用产线t=0至末任务结束的开机分钟，含等待和换型 |
| 均衡 | 1−σ/μ，七条线的生产时长/可用时长均计入，包含空闲线；负值保留，评分下限0 |
| 谷电 | 低价时段生产分钟 / 七条线全部低价可用分钟 |

分母0显示“不适用”。当前按前日20:00至当日20:00连续两班，不启用额外2小时；准备条件暂按已满足，统一交期20:00。电价借用 `data/v2/1130-3.txt` 历史样例，未计算真实电费。非常规2及上下水位均0的物料只补缺口，允许最小整批尾差。缺主数据/产能的4项在页面列出，未补造；其中5029505的20吨安全库存需求暂排除。七号线车间采用产线表。完整处理说明随运行快照保存。

## 开发入口

- `prompts/system.md`、`skills/feed-planning/SKILL.md`：本地提示词和排产Skill，每次调用读取。
- `data_loader.py`：Excel、数量边界、整批选项、换型矩阵。
- `agent_worker.py`、`agentcore_client.py`：AG-UI、JSON提案、流式阶段、取消。
- `solver_worker.py`：原求解器的隔离适配器，返回结构化结果。
- `evaluation.py`、`controller.py`：指标、硬门槛、循环及历史最佳。
- `conversation.py`、`planning_state.py`、`prompts/conversation.md`：多轮会话、指代、版本草稿、人工约束及意图解析。
- `app.py`、`static/`：本地API与前端交互。后续可将独立工具函数封装为MCP迁移。
- `runs/<ID>/`：输入快照、原始求解结果和完整记录；重启可回看，中断任务不自动续跑。
- `sessions/<ID>.json`：会话消息、冻结数据、草稿、配置与关联版本，保留在本机。

主要会话接口：`POST /api/sessions` 新建；`GET /api/sessions` 列表；`GET /api/sessions/<id>` 恢复/轮询；`POST /api/sessions/<id>/messages` 提交 `{"text":"查询5000611的需求"}`，或由前端提交白名单 `action`。原有 `/api/jobs`、任务取消、导出接口继续保留。

## 尚待业务接入

- **APS下达**：按钮保留但不发送；需要下达接口地址、鉴权、字段与回执。
- **实际生产历史/实时订单库存**：当前读取提供的 Excel 和本地计算记录；要显示工厂实时变化或某日实际生产，需要对应接口/数据。
- **客户订单交期、分段检修、准备条件和真实电价**：仍按下述 Demo 口径。已有车间两班时间已使用，不再将其列为缺失；未提供的分段停机不能用全天启停替代。
