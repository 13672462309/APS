# 饲料 APS 排产智能体需求文档

版本：1.0  
日期：2026-10-18  
适用范围：当前本地 Demo，以及后续 Agent 开发的业务基线  
配套文档：[设计文档](设计文档.md)

## 1 项目目标与范围

使用用户提供的 Excel 数据、原 HTML 交互原型和现有 `aps-feed` 求解器，形成可以实际操作的对话排产 Demo：

**查看和确认需求 → 确认目标 → Agent 调整排产计划 → 求解器计算排程 → 评估六项指标 → 反馈优化 → 输出方案 → 人工修改后再次优化。**

排产回答“各物料生产多少、优先生产什么”；排程回答“在哪条产线、按什么顺序、什么时间生产”。两者通过循环连接，但职责分开。

本期优先完成本地闭环。业务数据和求解器运行在本机；大模型通过已配置的 AgentCore 接口调用。后续再迁移云端工具和运行环境。

### 1.1 需求依据

| 依据 | 使用方式 |
|---|---|

| 原始 HTML 原型及用户截图 | 保留欢迎语、对话、快捷操作、阶段条、工作台与结果页交互；示例数据不能冒充真实数据 |
| `APS基础数据0814.xlsx` | 当前业务数据来源 |

本文使用“已实现”“Demo 口径”“后续”区分状态。“已实现”表示代码已有对应逻辑，不等于已经通过工厂生产验收。

### 1.2 职责划分

| 参与者 | 主要职责 |
|---|---|
| 计划员 | 查看需求，填写成品分解数量，确认目标与约束，选择方案，修改并重新优化 |
| 排产 Agent | 在允许范围内提出数量、优先级、优化侧重点调整，并说明预期作用 |
| 现有求解器 | 根据计划和约束计算产线分配、生产顺序、开始和结束时间 |
| Loop 控制器 | 校验提案、调用求解器、计算指标、保存最佳方案、判断停止 |
| 前端与业务后端 | 执行对话操作，管理草稿、版本、查询、解释和结果展示 |

## 2 核心业务流程

| 阶段 | 用户操作 | 输出与推进条件 |
|---|---|---|
| 数据校验 | 查看数据范围、异常、排除项与假设 | 确认可用于本次计算的数据；阻断问题需先处理 |
| 供需分析 | 查询需求、查看完整表单或单物料明细、填写数量 | 保存需求确认草稿，尚不自动求解 |
| 目标确认 | 设置覆盖期、侧重点、指标阈值、最大轮数等 | 明确点击“确认目标，开始求解”后运行 |
| 求解调优 | 查看进度，必要时停止 | 多轮候选、指标、问题及当前最佳结果 |
| 结果校验 | 查看约束问题、未排入任务和指标口径 | 区分可行方案与不可执行候选 |
| 方案输出 | 查看甘特图、负荷、订单明细、解释与导出 | 保留版本；可继续修改并开启新一轮 Loop |

数据校验、供需分析、目标确认之间必须可以返回。返回后，“继续”从当前页面推进，不能跳到曾经到达的最远步骤。仅查看、返回、保存数量或在目标页输入“继续”，均不得自动启动求解。

最终方案修改流程：

1. 从选中的已求解版本进入“修改产量”。
2. 修改成品分解数量或允许调整的约束，保存草稿。
3. 原方案继续保留，并明确提示“有未重算的修改”。
4. 点击“确认修改，开始优化”，以修改后的完整计划启动新版本。
5. 在新问题的候选中选择最佳结果。若没有可行结果，保留旧版本和修改信息，不把旧分数冒充新方案的计算结果。

## 3 数量字段与数据口径

### 3.1 用户确认的数量定义

**计划产量 = 同一物料各分解行的成品分解数量之和。**

用户在需求确认时填写“今天产多少吨”，填写对象是 **成品分解数量**。当前需求确认采用一物料一条分解行，因此成品分解数量等于计划产量。计划产量只读，由系统汇总，不设置第二个独立可编辑值。

业务上，后续可按产线或时段拆成多行，每行都有自己的成品分解数量。当前求解器没有开放跨线拆分；该能力属于后续扩展，不能由表格支持汇总多行推断为已经实现。

| 字段 | 定义与展示要求 | 状态 |
|---|---|---|
| 成品分解数量（吨） | 当前分解行计划生产量，人工填写或明确求解后生成；人工修改后须锁定 | 已实现一物料一行 |
| 计划产量（吨） | 各分解行成品分解数量之和；需求确认当前与上一列相等 | 已实现 |
| 建议生产量（吨） | 当前展示逻辑取最近可行求解方案的总量；求解前为空，草稿修改后待重算 | Demo 口径 |
| 继续生产量（吨） | Excel 前置生产订单中尚未完成的数量，按物料汇总 | 已实现，当前作为固定在制余量 |
| 内部新增量 | 当前适配器采用“分解行总量 − 固定在制余量”；不直接替代页面计划产量 | Demo 内部计算口径 |
| 缺口数量 | `min(0, 总供应量 − 本周期需求量)`；有缺口显示负数并标红，无缺口显示 0 | 已实现 |
| 总供应量 | 来自 Excel；当前按已经包含在制余量处理，不重复扣减在制 | Demo 口径 |
| 库存数量 | 当前取 `max(0, 总供应量 − 在制余量)`，不是独立仓库实盘值 | Demo 推算值 |

举例仅说明公式：覆盖需求 100 吨、供应 70 吨，则缺口显示 **−30 吨**。若其中固定在制 10 吨，人工填写总量 50 吨，则内部新增量为 40 吨；该值仍需通过整批、需求及库存校验。

未填写且未生成方案时，成品分解数量、计划产量和建议生产量显示“—”或“待填写”。不能把内部规则基准提前显示成用户已确认的计划，也不能把空值当作人工确认了 0 吨。

### 3.2 数量修改要求

- 入口应同时支持需求表填写、结果页“修改产量”和对话指令。
- 保存后同步计划产量，但保存本身不触发求解。
- 必须校验合法批量、最低需求、库存上限、固定在制和可用产线。
- 不合法时说明原因并提供合法数量参考，不静默取整，不部分保存一组修改。
- 人工明确修改的数量在后续 Loop 中保持不变；未锁定物料可以继续优化。
- 解除锁定后，Agent 才可在合法范围内重新调整该物料。
- 在制余量当前固定；人工输入总量不得小于该余量。

## 5 界面与交互要求

### 5.1 保留原 HTML 交互

保留原型的左右布局、欢迎内容、快捷提问、阶段条、操作按钮和结果切换。将示例反馈替换为实际接口结果；未接入功能应说明状态，不能用模拟成功消息代替执行。

原型中的示例工厂、日期、物料、订单和历史记录不能作为当前 Excel 的事实。真实版本历史只来自本地实际计算。

### 5.2 需求表与列表设置

- 默认将 **物料编号、物料** 放在最左侧，其余字段按用户确认的配置展示。
- 字段目录以用户提供的列表设置截图为依据，共 81 项，完整目录见设计文档附录。
- 设置面板支持搜索、显示或隐藏、冻结、列宽、拖动排序和上下移动。
- 提供参考配置与恢复默认；点“确定”生效并保存，点“取消”不保存。
- “查明细”后必须提供“返回完整表单”。筛选不能造成无法恢复全部物料。
- 字段须说明是 Excel 原值、计算值、映射值还是缺失数据；缺失显示“—”。
- 窄窗口可横向滚动。无法容纳冻结区域时可暂时取消固定，但保留用户的字段顺序与设置。

当前用户明确要求标负数并标红的是“缺口数量”列。现有 `T缺口`、`T+1缺口`、`T+2缺口`仍使用累计正缺口口径；若后续需要全表统一符号，应作为单独变更同步公式和展示。

### 5.3 订单明细

订单明细按原型保留七列：

| 订单号 | 物料 | 分类 | 产线 | 数量 | 交付 | 状态 |
|---|---|---|---|---|---|---|
| 缺失时为 — | 真实物料名称 | 真实产品分类 | 实际排入产线 | 当前计划总量 | 缺失时为 — | 依据真实排入结果判断 |

当前暂按物料汇总展示，并明确标注该粒度。没有客户订单号和逐订单交期时显示“—”，此做法已获用户确认。前置生产订单号不充当客户订单号，统一排程交期也不充当实际订单交期。

该页使用原型的独立明细表，不混排指标卡、轮次按钮和技术性任务起止时间表。数量入口、指标和优化操作在相应工作台区域保留。

状态包括已排入、部分排入、未排入、待检查。“已排入”仅表示已纳入当前排程，不表示已下达或已完成生产。

## 6 六项指标与优化目标

六项指标由后端根据求解结果计算，Agent 不直接生成分数。下表记录当前 Demo 的可计算口径，后续接入真实生产数据时需重新确认分母和时间窗口。

| 指标 | 当前计算方式 | 默认阈值 | 口径限制 |
|---|---|---:|---|
| 排产可行性 | 通过独立校验的计划数 / 本轮总计划数 | 100% | 校验产能、整批、开班、时长、换型、不重叠及人工约束；准备条件暂按满足 |
| 粒径从小到大 | 同产线粒径非递减的相邻对 / 可比较相邻对 | 95% | 任一粒径缺失的相邻对不统计 |
| 及时交付 | 统一交期内完成且通过校验的计划数 / 本轮总计划数 | 100% | 当前统一为生产日 20:00，非真实订单准交率 |
| 理论 OEE | 有效生产分钟 / 各开机产线从起点至末任务结束的分钟合计 | 85% | 包含等待与换型，不包含末任务后停机；不是包含质量、故障数据的完整 OEE |
| 产线均衡度 | `100 × (1 − σ/μ)`，负荷取生产时长 / 可用时长 | 80% | 固定七条产线含空闲线；原始值可能为负 |
| 谷电利用率 | 谷电时段生产分钟 / 七条产线的谷电可用分钟 | 80% | 使用历史电价样例；不等同实际电费节省比例 |

分母为 0 时显示“不适用”，不记为 0%。不适用项不参与阈值和软评分；必须仍通过整体可行性门槛。

固定缺口物料及在制任务还需通过独立的需求覆盖检查，防止通过减少必须生产的任务来提高指标。

指标可能相互冲突，不要求每一轮六项指标都上涨。当前选择原则是先满足硬条件，再按综合分比较。默认软评分权重为粒径 20%、交付 30%、OEE 20%、均衡 20%、谷电 10%；这些是 Demo 配置，不视为已批准的最终经营目标。

## 7 Loop 控制要求

| 参数 | 默认值 | 当前允许范围 |
|---|---:|---|
| 最大轮数 | 4 轮 | 1～10 轮 |
| 总时间预算 | 600 秒 | 30～1800 秒 |
| 连续无显著改进上限 | 2 轮 | 1～10 轮 |
| 最小显著分数提升 | 0.2 分 | 0～20 分 |
| 六项指标阈值 | 见第 6 节 | 0～100%；当前可行性、交付固定 100% |

满足下列任一条件即停止：

1. 方案可行，且所有适用指标达到阈值。
2. 达到最大轮数或总时间预算。
3. 连续若干轮无显著改进；硬约束表现改善也视为显著改进。
4. 返回已求解过的相同计划和优化侧重点。
5. 用户停止，或发生无法继续处理的调用、求解错误。

每轮保存提案、执行来源、指标、约束问题、是否成为最佳及停止原因。非法提案不能进入求解器，拒绝轮也要记录。

当前对话入口的第一轮先求解用户确认的基准计划，后续轮次再由 Agent 调整。最大轮数包含第一轮，因此设为 1 时不会进入排产 Agent 的迭代调整。直接任务 API 的首轮策略存在差异，见设计文档。

不保证有限轮数内达到全部阈值，也不宣称得到全局最优。预算耗尽时仍应返回已经取得的最佳结果及未达标项；若无可行方案，明确标识为问题候选。

## 8 数据边界与后续接入

当前运行数据可关联 115 个物料和 7 条产线；实际数量以每次校验结果为准。4 个缺少主数据或产能的供需项会列出排除原因，其中物料 5029505 的安全库存要求尚未纳入。不能将此称为完整工厂需求已经覆盖。

| 项目 | 当前处理 | 后续条件 |
|---|---|---|
| 车间班次 | 已有早班 08:00～20:00、晚班 20:00～08:00；按先晚班后白班计算 24 小时 | 不再将已有班次列为缺失 |
| 休息和检修 | 未提供独立分段窗口，当前不额外扣除 | 提供设备或产线不可用区间后扩展日历 |
| 客户订单明细 | 物料汇总需求，客户订单号和交期留空 | 客户订单接口或明细数据 |
| 原料与准备条件 | 暂按满足 | 齐套、清线、人员等所需校验数据 |
| 电价与电耗 | 历史样例时段，仅用于演示谷电偏好与统计 | 工厂实际分时电价及电耗口径 |
| 共享设备与蛋白等级 | 当前适配器未启用对应规则 | 共享关系和等级数据，以及明确约束规则 |
| 多行拆分 | 当前一物料一任务，不跨线拆分 | 扩展分解行模型、求解器、校验和订单汇总 |
| APS 正式下达 | 入口保留，未接入 | 接口、权限、回执、失败处理与幂等约定 |
| 规则表更新 | 当前按已编码规则运行，并记录文件指纹 | 建立规则到实现的映射；不能只改 Excel 就假设算法已同步 |

## 9 非功能要求

- **可追溯**：每次运行保存数据快照、文件指纹、参数、人工约束、各轮提案和评估结果。
- **结果一致**：显示、解释、导出使用同一版本；修改后的草稿与旧排程不能混为一个结果。
- **可恢复**：保存会话和历史；异常、取消、重启不得静默丢失已有成功版本。
- **本地边界**：当前服务仅本机访问，API Key 仅在后端配置；不将凭据写入前端和导出文件。
- **运行边界**：当前单进程同时运行一个优化任务；尚不承诺多人并发、企业权限或高可用。
- **数据真实性**：缺失数据不伪造，示例不冒充实绩；对话解释引用当前数据和计算依据。

| AC01 | 新建会话进入供需分析 | 使用 Excel 数据；未填写数量显示待填写，计划产量和建议生产量不提前出现规则值 |
| AC02 | 填写合法成品分解数量 | 自动汇总计划产量；保存后不启动求解；人工数量在后续 Loop 中不变 |
| AC03 | 填写非法量或批量修改含非法项 | 返回原因与合法参考；本组修改全部不应用，无静默取整 |
| AC04 | 存在需求缺口 | “缺口数量”展示负数并标红；无缺口为 0 |
| AC05 | 返回上一步后继续 | 从当前步骤推进；目标页仅“继续”不运行求解 |
| AC06 | 查询单物料明细 | 可返回完整表单，恢复全部物料；查询不改变计划与约束 |
| AC07 | 配置表格字段 | 物料编号、物料默认最左；显隐、宽度、冻结及排序确认后生效，刷新保留，取消无变化 |
| AC08 | 运行多轮优化 | 展示真实调用和求解进度、各轮指标与最佳结果；可追溯停止原因 |
| AC09 | 达阈值或达到轮数等上限 | 按第 7 节结束；保留已得到的最佳结果，不无限循环 |
| AC10 | 最终方案修改后重新优化 | 新建版本，不覆盖旧版；新版本使用修改后的数量和约束 |
| AC11 | 查看订单明细 | 仅原型七列，按物料汇总；缺失订单号及交付显示“—”；状态与真实排入结果一致 |
| AC12 | 指定不可生产的产线或冲突时间 | 能拒绝明显非法参数；求解后再独立校验，失败不能标为可执行 |
| AC13 | 停止、失败或服务重启 | 已完成版本保留；中断任务可识别，不宣称后台仍会自动完成 |
| AC14 | 导出及点击下达 | 导出与选中版本一致；无正式接口时下达操作明确说明未发送 |
