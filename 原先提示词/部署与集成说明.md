# 部署与集成说明（4 份专家提示词的落地方案）

> 配套文档：`编排专家提示词.md`、`需求计划专家提示词.md`、`优化求解专家提示词.md`、`输出生成专家提示词.md`

---

## 1. 总体集成架构

```
┌────────────────────────────────────────────────────────────┐
│ 会话前端（自建）                                             │
│  · 流式消息  · 选项卡片  · 结果预览   ← 会话启动时提交凭证    │
└───────────────────────┬────────────────────────────────────┘
                        │ 统一对话 API
┌───────────────────────▼────────────────────────────────────┐
│ Agent 运行时（高代码）                                       │
│  ├─ 编排专家提示词      → system prompt                     │
│  ├─ 3 份节点专家提示词  → 状态机节点级 prompt（代码内资产）    │
│  ├─ 状态机代码：六阶段流转 / 关卡 / 回退 / 断点续跑           │
│  └─ 配置渲染：启动时把参数符号替换为实际值                    │
├──────────┬──────────────────────┬──────────────────────────┤
│ Tools：   │ Sandbox：            │ Storage：                 │
│ 3 个数据源│ 自定义镜像（预装依赖） │ 挂载卷（阶段产物）         │
│ 工具 +    │ 8 个固定脚本          │ 结构化存储（摘要/偏好/    │
│ 凭证 Hook │ 模板文件              │ 追踪）                    │
├──────────┴──────────────────────┴──────────────────────────┤
│ Model 治理：模型路由 / 回退 / 限流 ｜ 可观测：全链路追踪       │
└────────────────────────────────────────────────────────────┘
```

**核心集成原则**：提示词只引用参数符号，实际值一律由平台层注入——**提示词文件本身不含任何环境相关的值**。

---

## 2. 参数注入总表

| 参数 | 内容 | 平台落点 | 注入方式 |
|------|------|---------|---------|
| `DATA_DIR` | 阶段产物与工作目录 | 沙箱挂载卷（对象存储 / 网络存储），挂载点为固定路径 | 沙箱模板的环境变量或挂载配置；提示词与脚本统一引用该符号 |
| `TOOL_LINES`<br>`TOOL_PRECHECK`<br>`TOOL_PRECONFIRM` | 数据源三个查询接口 | 工具注册中心：以 API 规格导入为函数调用工具，或注册为远程 MCP 工具；三个接口可聚合成一个工具网关统一端点 | 工具注册后获得工具标识；在 Agent 代码中与提示词参数名建立映射表 |
| `AUTH_TOKEN`<br>`AUTH_ENV` | 数据源认证凭证与环境标识 | 凭证托管 + 工具前置 Hook | 会话启动时由前端提交 → 写入会话状态 → **Hook 在调用前注入请求头，调用后记录审计**；不写入提示词、不写入日志 |
| `SCRIPT_PREPARE`<br>`SCRIPT_FMT_P1` / `_P2` / `_P34` / `_P5`<br>`SCRIPT_FILL_HTML`<br>`SCRIPT_SOLVE` / `SCRIPT_AUDIT` | **8 个固定脚本**：编排侧 6 件（数据准备 + 4 个展示层 + 可视化填充）＋ 求解侧 2 件（联合求解 + 独立审计） | 自定义沙箱镜像：脚本固化在镜像固定路径，依赖库一并预装 | 路径写入镜像约定；Agent 代码通过沙箱执行接口调用，提示词只引用符号 |
| `ATTRS_FILE` | 物料属性文件（换型等属性的全量字典） | 由 `SCRIPT_PREPARE` 产出于 `DATA_DIR`（与标准化输入包同目录） | 不单独注入：按 `DATA_DIR` 约定推导；缺失须报错终止，禁止兜底 |
| `HTML_TEMPLATE` | 可视化模板 | 同上（镜像内固化，或挂载卷内版本化管理） | 路径参数；模板变更属资产维护动作 |
| `STORE_SUMMARY`<br>`STORE_PREFS`<br>`STORE_TRACE` | 摘要 / 偏好 / 追踪存储 | 结构化存储（表或对象存储 JSON）；若平台提供记忆服务能力可承载偏好与摘要 | Agent 代码读写封装为存储适配层，提示词只引用句柄名 |
| `SOLVE_TIME_LIMIT`<br>`W_SECOND` / `W_CHANGEOVER` | 求解时长 / 两个权重 | 配置中心（工厂级可配） | 每次会话启动时按工厂读取 → 渲染进提示词 + 传给求解脚本命令行 |
| `AUTH_ENV`（环境） | 测试 / 生产 | 配置中心 | 同上，会话级选择 |

**脚本符号清点（防漂移，与提示词逐一对应）**：全流程共 **8 个**脚本符号——

| # | 符号 | 用途 | 由谁注入 |
|---|------|------|---------|
| 1 | `SCRIPT_PREPARE` | 数据准备（校验 + 覆盖周期 + 需求与上下界 + 输入包与属性文件落盘） | 编排节点 |
| 2 | `SCRIPT_FMT_P1` | 供需确认展示 | 编排节点 |
| 3 | `SCRIPT_FMT_P2` | 排产目标配置单展示 | 编排节点 |
| 4 | `SCRIPT_FMT_P34` | 求解状态与落位报告展示 | 编排节点 + 求解节点 |
| 5 | `SCRIPT_FMT_P5` | 结果文字版汇总 | 编排节点 + 输出节点 |
| 6 | `SCRIPT_FILL_HTML` | 可视化交付件填充 | 编排节点 + 输出节点 |
| 7 | `SCRIPT_SOLVE` | 联合求解 | 求解节点 |
| 8 | `SCRIPT_AUDIT` | 独立审计 | 求解节点 |

前 6 件由编排节点注入，后 2 件由求解节点注入（`SCRIPT_FMT_P34` / `SCRIPT_FMT_P5` / `SCRIPT_FILL_HTML` 在两处都会用到，同一符号指向同一路径）。`ATTRS_FILE` 不是脚本，由 `SCRIPT_PREPARE` 产出于 `DATA_DIR`。注册工具与准备沙箱时按此清单逐一核对，缺一即对应阶段报错。

**两种注入模式**：

| 模式 | 做法 | 适用 |
|------|------|------|
| 静态替换 | 部署前把符号替换为实际值写进提示词 | 单环境、参数极少变化；**不推荐**，参数变更需改提示词 |
| **运行时渲染（推荐）** | 提示词保留符号，Agent 启动节点前用当前配置渲染 | 多工厂差异化配置、参数频繁调整 |

## 3. 提示词投放位置

| 提示词 | 投放点 | 加载时机 |
|--------|--------|---------|
| 编排专家提示词 | Agent 的 system prompt | 会话启动，常驻 |
| 需求计划专家提示词 | 状态机 S0/S1 节点的节点级 prompt | 流程进入 S0 时注入 |
| 优化求解专家提示词 | 状态机 S3/S4 节点的节点级 prompt | 流程进入 S3 时注入 |
| 输出生成专家提示词 | 状态机 S5 节点的节点级 prompt | 流程进入 S5 时注入 |

**建议做法**：4 份提示词作为**版本化资产**管理（平台技能定义 / 代码包内 Markdown 文件均可），而非硬编码在业务逻辑里——便于灰度、回滚与差异对比。

**节点间回传**：直接用编排框架自带的消息传递机制（图的边 / 任务移交），不依赖任何外部平台专有的协作工具。

## 4. 工具与脚本集成清单

### 4.1 需注册的工具（3 项）

| 工具 | 类型 | 关键配置 |
|------|------|---------|
| 资源清单查询 | 函数调用 / 远程 MCP | 入参：凭证、环境、工厂、日期；出参：资源清单（产能、状态、初始产出物） |
| 物料供需预检 | 函数调用 / 远程 MCP | 入参：凭证、环境、资源列表、计划日期；出参：逐日需求、供应量、上下界、日均、产能列表 |
| 在制订单查询 | 函数调用 / 远程 MCP | 入参：凭证、环境、确认日期；出参：订单、资源、物料、计划量、继续生产量 |

**一致性要求**：工具在平台注册的名称/入参，必须与提示词里的参数符号一一对应，映射关系在 Agent 代码里显式声明（不要依赖模型猜）。

### 4.2 沙箱镜像内容（P0 必须完成）

| 项 | 要求 |
|---|---|
| 运行时 | Python 版本与求解器版本**匹配且固化**（版本不兼容会崩溃） |
| 依赖库 | 优化求解器、表格读写、绘图库全部预装；**运行期禁止安装包** |
| 8 个脚本 | 固化在镜像固定路径，与提示词参数符号一一对应（清单见第 2 节）；缺任一即对应阶段报错 |
| 模板文件 | 可视化模板随镜像或挂载卷提供，版本可追溯 |
| 网络策略 | 沙箱仅放通必要出网/内网策略（最小权限） |

### 4.3 存储与挂载

| 用途 | 建议落点 | 注意 |
|------|---------|------|
| 阶段产物（输入包 / 确认单 / 配置单 / 结果包） | 挂载卷按 `会话标识/阶段` 组织 | 属内部流程机制，不对外暴露 |
| 摘要 / 偏好 / 追踪 | 结构化存储 | 摘要按保留期清理；偏好按置信度累积；追踪供复盘 |
| 最终交付产物 | 对象存储 + 外链 | 唯一对外交付物，生成前须问询确认 |

## 5. 会话与状态

| 项 | 方案 |
|---|---|
| 会话亲和 | 平台能力，仅作性能优化，**不作为状态可靠性依赖** |
| 状态外置 | 当前阶段、已确认参数、产物引用全部写入结构化存储，凭会话标识可重建现场 |
| 长流程 | 排产流程可能跨小时，需支持断点续跑：任一阶段可从存储恢复并继续 |
| 关卡等待 | 用户确认/选项回答期间，运行实例可回收，用户回复后由状态机恢复 |

## 6. 可观测集成

| 项 | 做法 |
|---|---|
| 自研 trace_id | 与平台链路追踪关联：作为追踪属性 / 业务标签写入，便于跨系统检索 |
| 阶段耗时 | 每个阶段起止时间写入追踪存储，同时由平台自动记录工具调用耗时 |
| 工具调用 | 平台自动记录调用参数与结果；凭证字段须脱敏 |
| 成本归因 | 利用平台的用量与成本统计，按会话/工厂维度分析 |

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1 | 沙箱镜像可用 | 沙箱内导入求解器与绘图库成功 |
| 2 | 脚本可执行 | 8 个脚本在沙箱固定路径可运行，含模板文件 |
| 3 | 工具连通 | 三个数据源接口经工具网关调用成功，含凭证注入 |
| 4 | 存储可读写 | 挂载卷读写正常；结构化存储三个句柄可读写 |
| 5 | 配置可下发 | 工厂级参数可读取并渲染进提示词 |
| 6 | 追踪可见 | 平台链路追踪可检索到自研 trace_id |
| 7 | 前端可对话 | 流式消息 + 选项卡片 + 结果预览三项正常 |

## 8. 首个里程碑的集成验收（对应实施计划 P1/P2）

- **P1（不接模型）**：手工在沙箱按序运行 8 个脚本，产出与既有基准逐字段一致
- **P2（接模型）**：提示词渲染注入 → 状态机完整跑通一次任务 → 阶段输出全部由固定脚本生成 → 审计门禁通过

**集成相关的常见坑**：
1. 提示词里的参数符号与实际工具名不一致 → 节点找不到工具，行为漂移
2. 凭证写进提示词或日志 → 泄露风险，且过期后无法自动更新
3. 脚本路径写死在提示词里 → 换环境即失效
4. 把会话亲和当作状态存储 → 实例回收后流程丢失
5. 沙箱运行期安装依赖 → 冷启动变慢、环境不可复现
